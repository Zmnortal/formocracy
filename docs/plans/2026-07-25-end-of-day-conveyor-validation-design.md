# 日终送验传送带交互设计

## 目标

将现有的“列表勾选 + 整批确认”界面替换为概念图中的实体化流程：工作日结束后，待验档案袋排列在屏幕下方；玩家逐个选择档案袋，将其送上传送带并由现实验收机吞入。机器容量用尽或全部待验档案已经送入后，系统验证本批档案并进入日报。

## 视觉与布局

- 使用 `office_validation_room.png` 作为全屏 1280×720 验收室背景。
- 背景中央原有透视传送带与验收机作为视觉焦点，不重复叠加机器素材。
- 屏幕下方增加低矮的档案待装载区，最多显示六个封闭档案袋。
- 档案袋使用 `standard_closed.png`，每袋附档案号、申请人和原决定标签。
- 顶部状态条显示“现实验收”“已送入 N / 容量”“积压总量”。
- 中央传送带入口上方显示简短操作提示；文件袋悬停时抬起并提高亮度。

## 交互

1. 工作日案件全部归档后，召唤铃锁定，打开验收室。
2. 玩家点击一个档案袋。
3. 该档案袋先移动到传送带近端，再沿透视方向缩小并移入机器口。
4. 动画期间锁定其余档案袋，播放传送带音效。
5. 文件袋被吞入后，更新容量、剩余档案和机器状态。
6. 当送入数量达到机器容量，或待验档案已经全部送入时，自动执行本批验证。
7. 成功后发送现实验收回执并进入日报；未送入的档案保留在积压中。

## 状态与兼容

- 继续使用 `WorkdayState.manager.get_pending_archives()` 和 `validate_archive_batch()`，不改变存档格式。
- `selected_ids` 表示当前已被机器吞入、等待整批落效的档案。
- 保留 `select_first_up_to_capacity()` 与 `confirm(true)`，供现有自动化流程快速跳过动画。
- 不修改 `desk_item_controller.gd`；交互完全封装在 `WorkbenchBatchValidationModule` 内。
- 机器容量逻辑保持不变：第 1 日容量为 4，因此五宗案件中会有一宗进入次日积压。

## 验证标准

- 打开验收室时，待验档案袋数量与积压数量一致。
- 单次点击只吞入一袋，动画期间不能重复送入。
- 不得超过 `machine_capacity`。
- 送满后仅已送入档案变为 `EFFECTIVE`，其余仍为积压。
- 现实回执正常发送，随后进入 `daily_report.tscn`。
- 1280×720 截图中背景、机器、传送带、档案袋和状态文字无遮挡或裁切。
