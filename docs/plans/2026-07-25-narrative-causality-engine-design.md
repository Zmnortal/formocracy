# 单页叙事因果引擎设计

## 目的

用一张可交互页面回答三个问题：

1. 七天内有哪些关键剧情案件；
2. 某个案件被批准、驳回或未发生时，后续哪些人物、证据与案件会改变；
3. 当前哪些内容已经进入游戏，哪些仍属于叙事设计推演。

## 页面模型

- 横轴：第 1～7 天；
- 纵轴：共同居住、时间与生存资源、污染与封存档案、最后一枚章；
- 节点：11 个已进入当前七日配置的故事案件；
- 边：依据四份专项叙事文档整理的设计推演关系；
- 决策：每个节点支持“批准 / 驳回 / 未发生”三种模拟结果；
- 输出：直接结果、后续受影响节点、四项结局风险。

## 真实性边界

当前工作日配置中有 11 个故事案件，但没有启用基于 `case_seen`、
`case_not_seen` 或 `decision_is` 的条件排期。因此：

- 案件节点标记为“已接入”；
- 因果连线标记为“设计推演”；
- 模拟结果只用于理解和校准叙事，不宣称游戏运行时已经实现这些分支。

## 默认情景

页面默认选择第三天的 `CASE-S-X14-D3`：

- 批准：失踪月份进入正式记录，林与沈的信任提高，第六天夜间排队证据更完整；
- 驳回：共同居住仍不稳定，林会带更重的材料回来，但合作度降低；
- 未发生：失踪月份没有被揭开，第六天和第七天失去一条关键旁证。

## 视觉方向

采用旧式行政档案台风格：泛黄纸面、黑色铅字、印章红和琥珀色状态。
七日矩阵是主视觉，因果线覆盖其上；右侧检查栏承担决策与解释，避免拆成多页。

## 昼夜文案管理升级

页面增加“因果图 / 昼夜文案”双模式。昼夜文案模式使用内嵌的
`data/narrative/daily_dialogue.json` 基线，按七天和白天/夜晚编辑台词。
每条文案包含场景、说话人、语气、接入状态、来源和正文。

浏览器侧提供：

- 七日切换及白天/夜晚双栏；
- 台词增删与就地编辑；
- `localStorage` 草稿保存；
- 标准 JSON 导入、导出与复制；
- 恢复项目基线。

离线 HTML 不静默改写项目文件。导出的 JSON 需要人工确认后替换
`data/narrative/daily_dialogue.json`，避免浏览器草稿意外覆盖运行时配置。
