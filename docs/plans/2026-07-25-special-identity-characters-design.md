# 特殊身份人物与等待台词设计

## 目标

在现有 18 位人物之外新增 10 位具有显著公众身份的虚构人物。公众声望不能成为行政特权的简单代名词；每个人都必须因为姓名、住所、职业资格、保密记录或历史档案的矛盾，被迫进入第十二区的受理系统。

每位人物交付一套人物素材库资产：

- 人物完整设定与机器可读 JSON 元数据
- 独立全身图
- 由中立全身图统一裁切的 256×256 标准头像
- 128×128、纯黑白、低像素 NES 风格头像
- 至少 26 条结构化台词
- 人物档案 HTML 中的独立页面

## 台词结构

每人至少 26 条：

- `greeting`：3 条
- `delivery`：3 条
- `waiting_public`：4 条
- `waiting_personal`：4 条
- `waiting_identity`：3 条
- `waiting_story`：3 条
- `approved`：3 条
- `rejected`：3 条

等待台词按阶段推进，而不是从一个大池子随机抽取：

1. 等待约 8 秒后进入公众形象层。
2. 继续等待进入私人状态层。
3. 更长等待后透露证件与行政矛盾。
4. 最长等待才允许播放剧情线索。

同一案件中不重复已播放台词。人物离开窗口后重置进度；批准与驳回拥有独立反应池。

## 数据与运行时

人物基础资料继续存放在 `data/ontology/people.json`。结构化台词新增独立文件 `data/narrative/special_character_dialogues.json`，以人物 ID 为键，避免继续扩大案件文件中的单字符串 `dialogue`。

游戏案件仍可保留已有的单句字段。NPC 表演模块读取人物 ID 后，优先查找结构化台词池；不存在时回退到案件原有 `greeting`、`delivery`、`waiting`、`approved` 与 `rejected` 字段。这样旧 18 人与旧案件保持兼容。

人物 HTML 扩展为 28 人，并继续同时展示概念图、标准头像与 8-bit 头像。打包脚本不再假设人物数量固定为 18，而以本体与档案交集进行覆盖校验。

## 视觉规范

全身图延续项目现有的旧时代行政现实主义人物画风：正面、中立站姿、全身可见、服装带有职业识别，但避免舞台背景和过度装饰。生成源采用纯色抠图背景，进入项目后移除背景并归一化到 512×768。

标准头像只从中立全身图裁切，统一为 256×256 透明 PNG。8-bit 头像严格使用纯黑与纯白两色、低分辨率逻辑网格、128×128 最近邻放大，不使用灰阶、填充背景或装饰框。

## 验证

- 人物本体数量从 18 增至 28，10 个新增 ID 唯一且资源可加载。
- 每个新增人物恰好拥有完整全身图、标准头像和 8-bit 头像。
- 每人台词总数不少于 26，10 人合计不少于 260。
- 等待台词按阶段递进、单次案件不重复，并保留旧案件回退。
- 人物 HTML、人物 ZIP 和 Godot 核心玩法测试通过。
