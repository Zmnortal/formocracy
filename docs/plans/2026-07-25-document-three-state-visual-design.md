# 文档三态视觉系统设计

## 目标

首批将事项申请表、身份证、居住证明从统一占位模板替换为三种真正不同的文件类型。每一份逻辑文档共享同一组事实、判定与印章记录，但根据所在位置切换独立视觉状态。

## 三个视觉状态

- `pocket`：文件露在文档袋内时使用的局部缩略图，只表达“袋中有哪份文件”。
- `desk`：文件被拖到桌面后使用的透视平放图，隐藏不可读的小字号动态内容。
- `inspection`：玩家点击桌面文件后使用的正面审阅图，显示字段、头像和盖章结果。

三种状态均在 `data/ontology/document_types.json` 中配置纹理与逻辑尺寸。运行时不复制文档数据，仅切换纹理、尺寸及内容层可见性。

## 运行时职责

- `DocumentView` 持有文档事实、动态字段、头像和印章记录，并公开三态切换接口。
- `WorkbenchCasePresenter` 根据袋内预览、抽取、落桌和再次打开等交互调用对应状态。
- 审阅状态使用独立内容层与印章层；切换到桌面状态时隐藏动态文字，但不销毁印章记录。
- 不同文档类型允许拥有不同长宽比，例如身份证保持横向，申请表和居住证明保持纵向。

## 物料来源

- 申请表基于项目已有申请表素材清理。
- 身份证基于 `/Users/amin/Desktop/身份证.jpg` 清理。
- 居住证明参考 `/Users/amin/Desktop/世界观档案with图片.pdf` 中的居住证明视觉重制。

所有正式运行时物料均输出为透明 PNG，存放在 `assets/documents/types/<type>/`。

## 验证

- 自动验证三类文档均绑定三个独立纹理和不同状态尺寸。
- 验证身份证横向、两类表单纵向，且只有身份证显示头像。
- 验证袋内、桌面、审阅切换不会丢失文档事实或印章记录。
- 通过游戏内截图同时检查袋内预览，以及桌面平放与打开审阅的混合层级。

## 交互比例与文件袋自由移动

- 审阅态缩放为原先约 56%，源 PNG 和逻辑布局保持不变，确保缩小后仍使用完整分辨率。
- 事项申请表由类型配置提供受理单位、递交时间、递交方式和档案分类等预填写字段，案件数据仍可覆盖同名默认值。
- 文件袋能否移动与材料是否收齐彻底解耦。袋内材料状态只决定预览和送验资格，不再设置拖拽锁。
- 打开或平放状态均允许抓取文件袋；送入验收区仍严格要求全部材料归袋，避免“能移动”等价于“能违规提交”。
