# 日初秘书简报与召唤铃设计

## 目标

每天开始时由身份不明的秘书通过办公室广播向玩家说明昨日结果、今日规则和剧情变化。秘书不直接出现，只显示广播字幕和模糊拟声。简报结束后，玩家必须按下桌面实体召唤铃才能让第一位申请人进场；每个案件完成后也必须再次按铃召入下一位。

## 每日简报合成

简报由配置驱动，按顺序合成：

1. 当天固定简报。
2. 昨日审批结果触发的剧情片段。
3. 经济、信用、生活状态或持有表单触发的片段。
4. 主线与特殊事件片段。
5. 今日工作规则和召入提示。

每个条件片段包含条件、优先级、台词列表和 `once` 标记。导演只读取状态并筛选内容，不在演出代码中硬编码剧情。未识别的条件按不符合处理；单段配置异常不会阻止其他简报播放。

## 表现

工作台进入 `BRIEFING` 后保持可见，但案件物件和召唤铃锁定。秘书台词自动逐句播放，每句显示广播字幕并触发一次低音量、带广播感的抽象拟声。玩家无需点击推进。

全部台词结束后播放提示，状态进入 `WAITING_FOR_FIRST_CALL`，召唤铃亮起。秘书没有头像、模型或姓名；界面只标记为“内部广播”，使其可以被理解为人、AI 或制度本身。

## 召唤铃与案件状态

```text
BRIEFING
→ WAITING_FOR_FIRST_CALL
→ NPC_PERFORMANCE
→ PROCESSING_CASE
→ NPC_LEAVING
→ WAITING_FOR_NEXT_CALL
→ NPC_PERFORMANCE
→ DAY_FINISHED
```

召唤铃是工作台上的实体 `Control`，具有锁定、可用、按下三种表现。可用时指示灯轻微闪烁；按下后立即锁住并播放机械铃声，随后播放 0.5–1.2 秒的广播提示/静电，再发出 `called` 信号。重复点击不能产生多个 NPC。

案件启动从“立即进场”改为“准备案件数据但等待召唤”。NPC 完成结果反应并离场后，不自动推进下一位；系统准备下一案件并重新解锁铃铛。最后一案完成或工作时间结束时不再解锁，直接进入日终。

## 音频

- 桌面铃候选：OpenGameArt `Bell dings/chimes`，作者 PWL，CC0。
- 广播提示候选：Pixabay Intercom 分类中的短促 intercom tone 或 malfunctioning intercom 片段；只保留提示音与静电，不保留可识别人声。
- 秘书拟声：复用人物拟声系统，通过较低音量和稳定声线营造墙内广播感。

项目内保存来源 URL、作者、许可和修改说明。素材加载失败时使用现有 UI 音效降级，不能阻断召入流程。

## 开发工具与验收

开发者控制台支持跳过简报、播放下一句、解锁铃铛和强制召入。

- 固定内容和符合条件的非线性片段能按优先级合并。
- `once` 片段只播放一次。
- 简报结束前不能按铃。
- 每次铃铛只召入一名 NPC。
- NPC 离场后必须再次按铃才出现下一位。
- 最后一案结束后不开放铃铛。
- 音效缺失时完整流程仍可继续。
- 自动化回归和实际 Godot 渲染检查通过。
