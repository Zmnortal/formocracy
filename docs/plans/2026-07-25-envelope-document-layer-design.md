# 文件袋查验层与文件落桌交互设计

## 目标

文件袋在桌面态与查验态之间可重复切换。玩家点击桌面文件袋进入查验层；点击文件袋与文件之外的空白区域时，文件袋自动收回桌面。已经从袋中取出的文件不会随文件袋一起消失。

文件采用三个明确状态：

1. `BAG`：只以袋内缩略图存在。
2. `INSPECTION`：点击缩略图后以较大比例出现在查验层，可阅读和向下拖动。
3. `DESK`：文件拖过桌面上沿后缩成带纵向压缩的平躺纸张，成为普通桌面物件。

## 层级与输入

查验态创建一层全屏透明遮罩，位于桌面物件之上、文件袋和查验文件之下。遮罩只负责接收空白区域的左键点击并关闭查验层。文件袋与文件继续接收自己的拖拽和按钮事件，因此遮罩不会阻断文件向桌面的拖动。

层级顺序为：

`桌面物件 < 查验遮罩 < 文件袋 Billboard < 查验文件 < 当前抓取物`

文件落桌后回到桌面物件层；如果文件袋仍然展开，重叠部分可以被袋体遮住。点击空白处收起文件袋后，桌面文件完整显露。

## 拖放规则

查验文件向下越过 `DeskGeometry.BOUNDS_TOP` 后立即切换为 `DESK` 状态，更新桌面基础缩放，并继续跟随鼠标。放手后由 `DeskItemController` 使用现有桌面边界与重力逻辑完成落点。

重新装袋不再使用“文件矩形与整个文件袋相交”的宽泛判定。只有文件中心进入袋口/缩略图托盘区域时才调用 `pack_document`。这样文件可以安全落在文件袋前方的桌面区域，不会被误判为已经装袋。

## 验证

- 袋外空白点击后文件袋缩回桌面。
- 已拆开的文件袋可以再次点击展开，保留已取出与未取出的文件状态。
- 文件向下拖过桌面上沿后切换为平躺比例，并能在桌面内原地放下。
- 文件释放在袋体下方但未进入袋口时不会自动装袋。
- 文件中心进入袋口区域时仍可正确重新装袋。

## 真实袋口与再次查验

原始文档袋组图中的 `open_filled` 帧包含两张烘焙在图片里的假文件，不能代表当前案件材料；运行时黑色缩略图面板也破坏了袋口结构。打开后的袋体改用 `open_empty` 帧，袋口上方叠加当前案件各 `DocumentView` 的真实背景预览。预览采用透明、裁切的扇形排列，不再绘制黑色容器。

拆封不再依赖袋子底部的文字按钮。Billboard 封闭态只在圆环与上部封盖范围放置透明热区；点击后播放松绳、开盖，再显示真实文件。点击某份袋口文件时，同一个 `DocumentView` 从该预览的屏幕位置起步，经过位移、放大和轻微回正动画进入 `INSPECTION`，预览同步消失，因此画面上不存在“占位图与真实文件并存”。

`DESK` 文件保留桌面落点。单击后，它从原落点抬升并恢复可读比例；点击文件之外的空白区域时，它反向落回原位置和平躺比例。刚从袋中抽出、尚未在桌面落过的文件没有桌面落点，因此不会被空白点击凭空送回桌面，仍需玩家向下拖放。由此形成：

`BAG → 抽出动画 → INSPECTION → 向下拖放 → DESK → 单击抬起 → INSPECTION → 空白点击回落 → DESK`
