# 干净办事窗口与模块化工作台设计

## 目标

主玩法界面继续使用暗绿色、压抑、制度化的像素工业风，但不再让背景图承担所有信息和道具。画面采用清晰的办事窗口构图：NPC 是中央唯一主视觉，桌面保持足够留白，所有会变化、会交互或需要反馈状态的物件都使用独立节点。

参考图提供的是构图关系，不直接改变游戏已有的世界观：

- 中央是来访者与办事窗口。
- 下方是玩家可操作的工作台。
- 左右两侧只放辅助设施。
- 桌面道具由独立素材拼装，不绘死在背景中。

## 视觉分层

界面使用固定的五层结构，并通过明确的 `z_index` 避免 NPC、表单和 UI 互相遮挡。

1. **永久底景**
   - 墙面、立柱、窗口开口、远处走廊和基础光影。
   - 不包含表单、印章、档案柜、机器、提示文字或其他可交互物。
   - 维持暗绿、旧铜、灰棕色调，降低纹理对比度，为人物留出视觉空间。

2. **空间设施**
   - 左侧档案柜、号码机。
   - 右侧日历、任务板与归档托盘。
   - 这些元素来自 `office_item.png`，需要拆成透明 PNG 后单独放置。

3. **NPC 舞台**
   - 当前 NPC 位于窗口中央，完整显示全身。
   - 后续排队者只在窗口后方以缩小、降低透明度的方式出现。
   - 对话框位于 NPC 右上方，避免遮挡面部和身体。

4. **工作台交互**
   - 桌面占画面下方约 35%。
   - 当前表单位于中央，文件袋由窗口方向投递至桌面。
   - 绿章、红章固定在右下操作区。
   - 铃铛位于靠近窗口的桌面边缘。
   - 当日归档区位于右侧，完成封袋后才能接收文件。

5. **系统信息**
   - 时间、当日状态和 DEV 入口压缩为顶部窄条。
   - 当前申请人资料、队列说明等大面板默认移除或折叠。
   - 关键提示优先通过物件状态、灯光和短文本表达。

## 素材处理

`/Users/amin/Desktop/FORMOCRACY/office_item.png` 是 1536×1024 的 RGB 合图，没有透明通道。首轮拆分以下素材：

- 两层档案柜
- 号码机
- 空白纸张
- 日历
- 绿色批准印章
- 红色退回印章

拆分后的素材统一保存至 `assets/office/items/`。每张图保留像素边缘，不做平滑缩放；Godot 导入时关闭过滤，使用整数或接近整数的缩放比例。深蓝底色通过边缘连通区域去除，检查内部深色区域，避免误删号码机屏幕和档案柜阴影。

## 首轮布局

- 设计分辨率继续使用 1280×720。
- 窗口中心位于画面横向 50% 附近。
- NPC 可视区域约为 `x=430..820`、`y=150..490`。
- 桌面从 `y=470` 开始，向下延伸至屏幕底部。
- 左侧设施控制在画面宽度的 22% 内。
- 右侧设施控制在画面宽度的 22% 内。
- 表单核心阅读区不与左右设施重叠。

不同窗口尺寸继续使用项目当前的全屏拉伸策略。底景允许轻度裁切填满屏幕，交互节点按 1280×720 的设计坐标统一缩放，避免窗口拉伸后出现边缘空白。

## 交互与状态

- 独立道具节点的视觉位置同时定义其交互热区。
- 不可交互的空间设施使用 `MOUSE_FILTER_IGNORE`，避免阻断拖拽。
- 印章、铃铛、文件袋和归档区保持原有游戏状态机，不在视觉重构中改变判定规则。
- 日终批量送验作为独立覆盖层，不绘制进底景。
- 当素材缺失或加载失败时，保留现有程序化面板作为开发回退，避免主玩法无法启动。

## 验收标准

- NPC 是画面第一视觉焦点，面部与全身不被面板遮挡。
- 背景中不再出现与真实交互节点重复的印章、表单或机器。
- 桌面至少保留 40% 的无杂物区域供表单拖动与展开。
- `office_item.png` 中选定的六类素材可以独立显示、移动和隐藏。
- 原有开袋、拖表、勾选、盖章、封袋、归档与召唤铃流程全部可用。
- 1280×720 和更宽窗口下不出现黑边、右侧截断或交互热区偏移。
- 自动化测试通过，并对主流程截图进行人工视觉检查。
