# 关键 NPC 多句对白设计

**状态：Active**

## 目标

关键故事案件需要比普通行政案件承载更多人物信息、证据与情绪，但不能把单句写成塞满气泡的长段落。普通案件继续保持短促、日常的办事节奏；只有 `content_kind: "story"` 的案件获得多句对白。

## 方案选择

采用兼容式对白序列：`greeting`、`delivery`、`waiting`、`approved`、`rejected` 五个字段同时接受字符串或字符串数组。旧案件无需迁移；故事案件可将一个阶段写成 2–3 个短句。运行时统一把字段归一化为 `Array[String]`，忽略空句并按顺序播放。

没有采用“单个长字符串”，因为现有 NPC 气泡只有 310×98，长段落会降低可读性。也暂不加入玩家追问选项，因为它会引入新的交互、状态分支与内容回收要求，超出这次扩写范围。

## 演出规则

- 问候与递件序列播放完毕后才开放材料。
- 等待序列仍在原延迟后触发；玩家先作决定时立即取消剩余句子。
- 批准或驳回反馈播放完毕后，NPC 才离场。
- 玩家仍可通过点击补全、关闭当前句并推进到下一句。
- 跳过演出会取消整个剩余序列，保持现有快速操作能力。
- 每句只承担一个功能：人物立场、事实线索、关系暗示或决定后果。

## 内容范围

首轮扩写覆盖七日内容包中的 11 个故事案件，重点人物包括林默、沈青禾、徐乔、杜葵、宋铎、孟岚、顾砚与魏澜。普通案件继续使用字符串字段，形成明确的节奏差异。

## 验证

- 验证字符串和数组都能被运行时读取。
- 验证 11 个故事案件的五个对白阶段均至少包含两句。
- 验证对白不存在空句，单句长度适合当前气泡。
- 运行 NPC 演出、七日叙事内容包与 Ontology 回归测试。
