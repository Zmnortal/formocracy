# FORMOCRACY 配置驱动关卡系统设计

## 目标

策划通过 Excel 或飞书表格配置关卡人物、申请事项、出场顺序和基础条件分支，无需修改 GDScript。Excel 是策划源文件，游戏读取导出的 UTF-8 CSV。

第一版支持角色与申请分离、固定主线角色与随机普通角色混排，以及一种基础前置条件：“指定历史案件的决定等于批准或驳回”。条件不满足时由普通角色池补位，固定随机种子用于复现队列。

## 配置工作簿

工作簿包含四张表，分别导出到 `data/config`：

- `characters.csv`：`character_id`、姓名、公民编号、头像路径、角色类型、标签、备注。
- `cases.csv`：`case_id`、`character_id`、部门、表单编号、申请内容、三条审查项、正确决定、池标签。
- `levels.csv`：`level_id`、工作日、案件数量、普通池标签、随机种子、日报标题。
- `level_slots.csv`：`level_id`、槽位、固定 `case_id`、是否主线、前置 `case_id`、前置决定。

角色只定义一次。同一个角色再次登场时，新增一条关联相同 `character_id` 的案件。

## 运行架构

新增全局 `ConfigDatabase`，启动时读取和校验四张 CSV，将数据整理为以 ID 为键的字典。它只负责加载、查询与错误报告。

新增 `LevelDirector`，根据 `level_id` 建立当天队列：

1. 按槽位检查固定主线案件。
2. 查询 `WorkdayState` 判断前置决定。
3. 条件不满足时从普通池补位。
4. 使用关卡随机种子洗牌，并避免当天重复案件。
5. 向主场景返回下一个完整案件数据。

主场景移除硬编码 `CASES`，只负责请求、显示和处理当前案件。提交后将 `case_id`、`character_id` 与决定写入 `WorkdayState`，再请求下一个案件。

`WorkdayState` 增加历史决定索引，并从当前关卡读取 `case_count`，不再把每日三件写死。

## 容错与开发工具

加载时检测缺少列、空或重复 ID、缺失角色、错误关卡/案件引用、非法决定与普通池不足。无效普通案件会被跳过；无效或条件不满足的主线案件由普通池补位。整个关卡无法形成有效队列时显示配置错误页面，不能进入空表单或死循环。

开发者控制台增加关卡选择、随机种子、重载配置、查看当前队列和跳转槽位。

## 测试与边界

自动化测试覆盖 CSV 中文与转义、数据关系校验、固定主线、条件补位、随机种子复现、当天去重、主场景推进与按 `case_count` 生成日报。

第一版不直接解析 `.xlsx`，不提供游戏内配置编辑器，不实现复杂表达式、概率剧情树或远程热更新。

完成标准：策划仅修改并导出四张表，即可改变 Day 1 的人物、申请内容、案件数量、主线位置、随机普通池和基础决定分支。
