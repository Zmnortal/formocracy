# 持久排队式 NPC 演出设计

## 目标

主玩法不再让每位 NPC 从场外重新走进来。角色以纵深队列持续存在：最前方角色正面服务，后排角色在其后叠放并以纯黑乘色压暗。前一位完成审批并离场后，下一位真实补到前排并恢复正常亮度，等待玩家再次按铃开始服务。

首版优先验证队列、补位与审批循环，暂缓 `walk_in` 和 `arrive` 演出，也不在本次改动中重新制作半身美术。

## 队列槽位

场上最多显示三名角色：

| 槽位 | 黑度 | Alpha | 作用 |
|---|---:|---:|---|
| 前排 | 0% | 100% | 当前服务对象 |
| 后排一 | 60% | 100% | 下一位申请人 |
| 后排二 | 75% | 100% | 再下一位申请人 |

“黑度”通过角色原始颜色向纯黑插值实现，不改变透明度。每个后排角色仍保持完整实体轮廓。后排越深，位置越靠后、尺寸越小、`z_index` 越低。

队列节点与案件 ID 必须成对持久保存。不得在每次按铃后清空并重建整条队伍，否则补位只会成为短暂的视觉假象。

## 演出状态

```text
FRONT_STAGED
  → 玩家按铃
  → GREETING
  → DELIVERING
  → WAITING / BREATHING
  → APPROVED_REACT 或 REJECTED_REACT
  → RESULT_IDLE
  → EXITING_LEFT
  → QUEUE_PROMOTING
  → FRONT_STAGED
```

第一位 NPC 在案件开始时已经位于前排，因此没有 `walk_in`、`arrive`、进场脚步或淡入缩放。角色完成问候后播放递交动画，文件袋交到工作台，再进入循环呼吸与低频微表情。

审批结果确定后，停止呼吸和微表情，播放 4–6 帧的批准或驳回表现，再保持对应情绪离场。首版所有角色向画面左侧退出。

## 补位

当前角色离场结束后立即释放其动画播放器和节点。后排一移动到前排位置，并在约 0.35 秒内完成：

- 黑度从 60% 过渡到 0%。
- 尺寸从后排比例恢复为角色本体前排比例。
- `z_index` 提升为前排层级。

其余后排角色同时向前移动一个槽位，并根据新槽位更新黑度。补位结束后角色处于 `FRONT_STAGED`，不会自动递交；玩家仍需按铃开始下一人的服务流程。

下一次案件启动时，若案件 ID 与已补位角色一致，应原位将候场静态角色升级为 `AnimatedSprite2D`，不得出现闪烁、位置跳变或先清空再生成的空档。

若工作时间结束或当天没有下一案，不提升幽灵角色。

## 动作帧数

| 动作 | 帧数 |
|---|---:|
| `idle` / 呼吸 | 3 |
| `blink` / `look_aside` | 3 |
| `nervous` | 4 |
| `deliver` | 4 |
| `happy_react` / `angry_react` | 4–6 |
| `happy_idle` / `angry_idle` | 3 |
| 离场动作 | 4–5 |

原有 `walk_in` 资源可以保留供未来使用，但当前状态机不调用。

## 跳过与异常

- 跳过问候或递交：直接进入 `WAITING`，但只发射一次 `delivery_finished`。
- 跳过结果或离场：统一经过幂等的离场收尾，释放当前角色并正确补位。
- 动画帧缺失：继续使用既有动作回退链。
- 补位角色与下一案件 ID 不一致：丢弃候场节点并按数据重建，记录开发警告。
- 场景退出：停止语音、脚步、动画令牌和所有排队 Tween。

## 验收标准

- 第一位 NPC 直接在前排递交，不播放进场动作或进场脚步。
- 后排角色 Alpha 始终为 1，黑度依次为 60% 和 75%。
- 批准与驳回分别播放对应结果动画。
- 当前角色统一向左离场。
- 离场后后排一真实补位，恢复 0% 黑度，并保持到再次按铃。
- 下一次按铃不会清空或闪烁整条队伍。
- 最后一位离场、工作日结束和跳过演出不会生成幽灵角色或重复信号。
- 自动化测试与实际渲染快照同时通过。
