# 文件袋与多文件审阅系统设计

## 目标

将主工作台现有的文件袋与文件 `Panel` 占位实现，替换为可持续配置和扩展的正式玩法系统：

- 案件到达时，桌面上只出现一个标准文件袋小图标。
- 打开文件袋后，显示袋内文件缩略图。
- 点击缩略图可在主审阅区展开正式文件。
- 多份文件可以同时展开、拖动、互相覆盖；点击文件时将其置顶。
- 展开的文件必须逐份拖回打开的文件袋，全部收回后才能送验。
- 印章可盖在任意展开文件上，同一文件允许保留多枚章以及互相冲突的章。

## 方案选择

采用“文档类型模板物料 + 代码填充字段”的结构。每种文件类型只维护一张不包含案件正文的像素风背景图，背景图负责纸张、边框、机构标识、固定栏目和磨损；案件配置只保存姓名、地址、编号、事项等实际数据；文档模板配置负责字段坐标和显示格式。

不采用逐案件完整图片，因为任何字段变化都会要求重新生产图片。不继续使用纯 Godot `Panel` 绘制，因为难以达到正式公文物料的质感和一致性。

## 首批物料

首日完整替换现有占位物料：

1. 标准文件袋关闭状态
2. 标准文件袋打开状态
3. 申请表模板
4. 身份记录模板
5. 居住证明模板
6. 知情声明模板
7. 诊疗站回执模板

正式文件采用统一逻辑尺寸 `640 × 480`。文件袋采用 `320 × 192`。图片使用透明 PNG 与最近邻过滤。文件模板中不烘焙案件数据，避免 AI 生成文字错误并保证策划可配置。

## 数据模型

文档类型配置增加：

```json
{
  "id": "DOCTYPE-IDENTITY",
  "background": "res://assets/documents/identity_record.png",
  "fields": {
    "name": {"label": "登记姓名", "position": [122, 164]},
    "address": {"label": "登记住所", "position": [122, 214]}
  }
}
```

运行时每份文件保存：

- `document_id`
- `document_type_id`
- 桌面位置与层级
- 是否展开、是否装袋
- 章列表

每枚章保存：

- `kind`：批准或驳回
- `document_id`
- 文件内部相对坐标
- 轻微旋转角度
- 盖章顺序

章作为所属文件的子节点渲染，因此拖动、置顶、缩放和装袋时自动跟随文件。

## 交互状态

### 文件袋

文件袋初始为关闭的小图标。NPC 递交后，玩家将其放到桌面并点击封口打开。打开后，文件袋留在桌面下部，袋内文件以缩略图形式排开。

### 文件

点击缩略图会展开对应文件。多份文件可以同时存在于主审阅区。拖动或点击文件会提高其层级。缩略图保持可见，用于重新找到被其他文件遮挡的材料。

玩家将展开文件拖回打开的文件袋后，该文件缩回并隐藏，但其字段、桌面状态和所有印章不会丢失。袋内全部文件收回后，文件袋进入可封装、可送验状态。

### 盖章

印章只能命中展开文件的实际矩形。每次落章生成独立印章节点并记录相对坐标。任何文件都能盖章，同一文件可以盖多个批准章、多个驳回章，也可以同时存在批准与驳回。

提交时不阻止错误操作，而是记录：

- 未盖任何章
- 批准与驳回并存（裁决冲突）
- 文件未全部重新装袋
- 遗漏材料

盖章先沿用现有音效接口，未来替换用户提供的音频文件时不修改交互逻辑。

## 实施阶段

1. 生产并验收首批七张像素物料。
2. 建立文档模板配置与 `DocumentView` 组件。
3. 重构 `CasePresenter`，实现文件袋缩略图、多文件展开、拖动与置顶。
4. 重构 `StampManager`，实现任意文件多章、相对坐标和冲突记录。
5. 更新装袋、提交、存档与程序错误数据。
6. 完成自动化测试和实际渲染检查。

## 验收标准

- 第一日所有文件不再显示代码生成的占位卡片。
- 文件袋初始是小图标，打开后才显示材料。
- 多份文件可以同时展开、拖动和互相覆盖。
- 点击文件或缩略图能将文件提到最上层。
- 每枚章绑定具体文件，并在移动和重新打开后保留。
- 玩家必须逐份将文件拖回文件袋。
- 冲突印章会形成程序错误，不会被系统静默覆盖。
- NPC、归档、日报、存档和眼镜同步流程无回归。
