# NPC 排队、角色演出与自动台词设计

## 目标

把案件从“文字和占位表单瞬间出现”改造成具体人物来到窗口办理事务的完整演出。NPC 不仅提供案件数据，还要通过排队、进场、递交、等待、说话、结果反应和离场，让玩家感受到审批决定作用在真实的人身上。

NPC 演出全程计入工作日倒计时。演出本身也是官僚系统效率压力的一部分。

## 画面布局

- 当前 NPC 位于画面中央偏左、办公桌后方。
- 后续两至三名 NPC 沿左后方形成纵深队列。
- 远处角色尺寸更小、亮度更低，越接近窗口越大、越清晰。
- 中央现实验收机器保持无遮挡。
- 文件袋从当前 NPC 手部移动到前景投递区。
- 台词气泡跟随当前 NPC，并限制在安全区域内，不能遮挡主表单、文件袋、印章或机器入口。

## 演出状态机

```text
QUEUED
→ WALKING_IN
→ GREETING
→ DELIVERING
→ WAITING
→ REACTING
→ WALKING_OUT
→ QUEUE_ADVANCING
```

- `QUEUED`：显示后续人物剪影。
- `WALKING_IN`：当前人物由左后方向办理位移动，同时放大、变亮。
- `GREETING`：播放呼吸动画并自动显示进场台词。
- `DELIVERING`：人物前倾或伸手，文件袋从人物处移动到桌面；完成前玩家不能操作文件袋。
- `WAITING`：人物保持等待动画；按案件配置自动触发一次等待台词。
- `REACTING`：机器吞入完成后，根据批准或驳回播放不同动作与台词。
- `WALKING_OUT`：结果台词仍可显示，人物开始向左侧离场。
- `QUEUE_ADVANCING`：后方人物整体前移，下一人进入。

## 自动台词

台词无需玩家点击，显示数秒后自动消失，也不会暂停工作日计时。

每个案件支持：

- `greeting`：进场台词
- `delivery`：递交台词
- `waiting`：等待台词
- `waiting_delay_seconds`：等待多久后触发
- `approved`：批准结果台词
- `rejected`：驳回结果台词

显示时间根据文本长度计算，并允许配置覆盖。等待台词每个案件只触发一次；文件袋进入机器感应区后不再触发新的等待台词。

## 角色素材结构

角色配置至少支持：

- 角色 ID
- 显示名
- `SpriteFrames` 或帧序列路径
- 基础显示尺寸
- 色调
- 移动速度
- 通用等待台词
- 动画映射：`walk`、`idle`、`deliver`、`approved`、`rejected`

第一版覆盖林默、周循、许桥。当前只有一套呼吸帧，因此三名角色先共用基础动画，通过色调、尺寸和轮廓附件区分。当前人物使用完整亮度；排队人物使用缩小、压暗的剪影。

正式素材缺失时必须降级：

- 无 `walk`：用位置 Tween、轻微上下起伏表现行走。
- 无 `deliver`：用前倾、横向位移和手部方向缩放表现递交。
- 无结果动画：批准用点头和松肩，驳回用停顿、下沉和后退。
- 无角色贴图：使用带轮廓的程序化人物剪影。

## 数据与流程接入

人物本体保存通用外观和动画资源。案件实例保存本次办理的台词与等待触发时间。`CaseSequence` 负责队列数据，独立 `NpcPerformanceController` 负责视觉状态机。

案件开始时先启动 NPC 进场，而不是立即创建可操作文件袋。`DELIVERING` 完成后才调用案件展示器生成或启用投递物。机器完成吞入后，审批结果先传给 NPC 控制器；离场结束后才推进 `CaseSequence`。

## 开发者工具

开发者控制台增加：

- 跳过当前演出
- 强制播放进场、等待、批准或驳回状态
- 显示当前 NPC 状态
- 重放递交和离场

## 第一版不做

- 口型同步
- 玩家对话选项
- 分支对话树
- 复杂寻路
- 多名 NPC 同时说话
- 三套正式完整角色动画

## 验收标准

- 当前 NPC 与后续队伍均可见，层级不遮挡核心交互。
- 文件袋只能在递交完成后操作。
- 进场、等待和结果台词会自动出现并消失。
- 批准与驳回具有不同动作和台词。
- NPC 完全离场后才进入下一案件。
- 演出期间工作日倒计时持续减少。
- 缺失动画资源时仍能完成完整流程。
- 自动化状态测试、旧主玩法回归和实际 Godot 渲染检查通过。
