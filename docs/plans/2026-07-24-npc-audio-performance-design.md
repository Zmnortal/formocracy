# NPC 声音演出设计

## 目标

在现有 NPC 排队、自动台词和审批反应之上加入抽象声音表演，让玩家在不增加完整语音成本的情况下感受到人物进场、开口、递交材料和离场。声音不能遮盖盖章、机器吞纸等关键操作反馈。

## 声音时序

```text
WALKING_IN  → 循环或持续播放脚步声，抵达窗口后停止
GREETING    → 气泡出现时播放一次人物拟声
DELIVERING  → 台词拟声 + 一次文件递交声
WAITING     → 等待台词出现时播放一次人物拟声
REACTING    → 批准或驳回台词出现时播放一次人物拟声
WALKING_OUT → 播放脚步声，离场结束后停止
```

人物拟声不朗读中文、不随每个文字重复触发，也不循环到整句结束。每个气泡最多播放一次短促声音，维持类似官僚模拟游戏的抽象表达。

## 数据配置

角色本体在 `people.json` 中配置 `voice_sfx`，值为项目内的资源路径。不同角色使用不同年龄或性别的短促拟声建立辨识度。脚步和递交声音为演出系统的通用配置，不写入案件数据。

角色未配置声音、路径失效或资源加载失败时，台词仍正常显示，演出不会中断。首版不增加音高随机、语速合成或口型同步。

## 播放器与生命周期

`NpcPerformanceController` 创建两个互不抢占的播放器：

- `voice_player`：人物台词拟声，同一时刻只允许一段。
- `movement_player`：脚步和递交等动作反馈。

开始新案件、开发者跳过演出、当前角色离场完成或场景退出时停止两个播放器。新台词出现前先停止旧拟声，防止快速切换状态时叠音。脚步在人物抵达窗口和离开画面时立即停止。

音量以关键操作反馈为主：人物拟声和脚步低于盖章、机器与错误提示。现有全局音效关闭状态继续由 Godot 音频总线负责，不在演出控制器内另建设置系统。

## 验收

- 三名 Day 1 NPC 能使用不同拟声。
- 进场与离场有脚步反馈，抵达后不会继续播放。
- 每个自动台词气泡只触发一次拟声。
- 递交阶段有一次动作声音。
- `npc skip`、案件切换和退出场景不会残留声音。
- 资源缺失时演出和交互仍能完整进行。
- 自动化回归与实际运行验证通过。
