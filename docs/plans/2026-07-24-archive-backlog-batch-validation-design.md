# 无限归档与有限批量送验设计

## 核心目标

把“每处理一案就送入机器”改成两层权力流程：

1. 白天玩家可以无限审批并把封好的文件袋归档。
2. 日终机器只允许有限数量的档案取得现实效力。

审批决定不再等于立即生效。玩家必须在日终有限容量中选择哪些档案送验；未选择的档案跨日积压，未来仍可再次选择。

## 白天案件流程

```text
按铃召入
→ NPC 从中央远处走到窗口正中
→ 递交文件袋
→ 玩家拆袋、检查、勾选与盖章
→ 所有材料重新装回原袋
→ 文件袋封口
→ 拖入当日归档区
→ NPC 反应并离场
→ 再次按铃
```

中央机器白天锁定并显示“日终统一送验”。文件袋进入归档区才算案件处理完成；归档容量无限。归档成功后，文件袋缩小为带编号、申请人和决策标识的档案脊，加入当日堆叠。

## 持久档案

每次归档生成独立的长期档案对象：

- 档案 ID
- 案件 ID、申请人和事项
- 审批决定及程序错误
- 归档工作日
- 已等待天数
- 来源为当日或历史积压
- 是否已装入日终托盘
- 是否已送验
- 生效工作日

状态为：

```text
PROCESSING → ARCHIVED → LOADED → EFFECTIVE
```

从托盘撤回的档案回到 `ARCHIVED`。未送验档案不会作废；进入下一天后等待天数增加。

## 日终批量送验

工作时间结束后停止开放召唤铃，完成当前案件并进入送验模式。当日归档与历史积压合并显示。

每天的 `machine_capacity` 由关卡配置决定。玩家将不超过容量的档案拖入送验托盘，界面显示 `已装载 N / M`。玩家可以查看档案摘要并从托盘撤回。

确认后，整个托盘以伪 3D 倾斜、缩小和遮罩动画进入中央机器。托盘内档案统一变为 `EFFECTIVE` 并记录生效日；未选择档案保持 `ARCHIVED`，进入积压库。随后进入日报和经济结算。

批准与驳回档案都必须送验才正式生效。日报分别统计今日审批数、今日归档数、今日送验数和积压总量。

## 配置与剧情

关卡配置新增：

- `machine_capacity`
- 日初简报中的容量播报
- 可选的送验优先提示

积压可触发条件剧情：等待超过指定天数、特定申请长期未生效、玩家批准后迟迟不送验、积压总量达到阈值等。首版不设置归档上限，也不自动替玩家选择送验对象。

## 验收标准

- 三名透明全身 NPC 在中央正确显示，层级不遮挡文件交互。
- 封袋后只能归档，白天不能直接送机器。
- 归档数量不受限制。
- 案件归档并且 NPC 离场后才开放下一次召唤。
- 日终送验容量来自当天配置。
- 超过容量的档案不能装入托盘。
- 未送验档案跨日保留并增加等待时间。
- 被送验档案取得现实效力并从积压库移除。
- 旧存档缺少新字段时能够安全迁移。
- 自动化回归、存档测试与实际 Godot 渲染检查通过。
