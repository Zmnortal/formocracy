# 表单视觉系统改造

## 目标

在工作台最终显示尺寸下，让玩家先识别表单功能，再阅读关键字段，最后检查辅助信息。视觉不得泄露该表单是否合规，也不得代替玩家作出批准或驳回判断。

## 视觉语法

- 颜色只编码功能类别，并在所有日期与场景中保持稳定。
- 每类表单使用一个 7×7 像素图标，避免依赖字体中的 Emoji。
- 表单顶部使用单一类别色带；正文不再使用密集表格、方格与重复分隔线。
- 字段使用浅色块和一条类别色竖边分组，不绘制完整边框。
- 布尔信息使用中性的实心/空心符号，不使用红绿表示对错。

## 信息层级

1. 类别图标、类别名称和表单标题。
2. 申请事项、声明事项、原因、摘要等核心字段。
3. 姓名、证件号、地址、状态等核验字段。
4. 受理单位、递交时间和档案分类等辅助字段。
5. 页面底部保留安静的盖章空间。

## 可读性约束

查验态以 0.36 倍显示，因此标题至少使用 34–42px 的文档逻辑字号，字段值至少 28–32px，字段标签至少 22–24px。换算到 1280×720 工作台后，关键信息应保持约 10–15 个逻辑屏幕像素。

## 交互边界

改造只影响查验态内容层。拖拽、桌面平放、抬起、盖章、多文件叠放、重新装袋与验收机提交继续使用同一个 `DocumentView`，不改变业务状态或判定规则。
