# 下班地图与个人生存表单系统设计

## 设计目标

主人公既是表单制度的执行者，也是制度的消费者。白天，玩家审批他人的生活申请；下班后，玩家必须购买并填写自己的表单，才能维持饮水、通勤、供电和医疗等基本生活。

该系统为日薪、绩效和罚款提供实际用途，并让白天的官僚规则在夜间反作用于玩家。

## 每日完整循环

```text
白天审批
→ 内部日报与经济结算
→ 下班过场
→ 第十二区档案地图
→ 最多两次地点行动
→ 回家填写一张个人表单
→ 生活状态与延迟申请结算
→ 次日上班
```

### 下班过场

日报关闭后播放约十秒的过场：

1. 办公室逐层熄灯。
2. 主人公收起个人档案袋。
3. 门禁机打印当晚允许活动的时段。
4. 画面切换到第十二区档案地图。

过场首轮完整播放，后续允许加速或跳过。

## 地图行动

主人公首版设定为独居。每晚拥有两次行动。

- 点击地点卡片后，角色 Token 沿红色路线移动。
- 抵达一个地点消耗一次行动。
- 玩家可以随时选择回家并结束夜晚。
- 未使用的行动转化为休息，不兑换金钱。
- 行动耗尽后只能回家。

地图不是自由行走场景。地点交互通过档案卡、机构窗口和实体表单完成，以保持与主工作台一致的纸质操作语言。

## 地点

| 地点 | 首次开放 | 主要功能 |
|---|---:|---|
| 住宅 | Day 1 | 填写个人表单、休息、查看生活状态 |
| 配给站 | Day 1 | 饮水与食品表单 |
| 住房管理处 | Day 2 | 供电、维修与住房表单 |
| 交通管理局 | Day 3 | 通勤与夜间通行表单 |
| 基层医疗站 | Day 4 | 医疗登记与药品领取表单 |
| 就业局 | 后续 | 工作证明、岗位保障和权限表单 |
| 中央表单部 | 特殊事件 | 利用职务权限加速或插队个人申请 |

Day 1 只显示住宅、配给站和中央表单部，其余地点以封条或锁定图章表示。

## 地点交互

玩家悬停地点卡时，卡片轻微抬起并产生硬边阴影。点击后：

1. 路线节点依次亮起。
2. 主人公 Token 沿路线分段移动。
3. 抵达后从地图上方展开机构窗口卡。
4. 窗口展示营业状态、表单目录、工本费和持有数量。
5. 购买时，实体表单滑入个人档案袋。

地点可能因日期、事件、通行许可或营业时间关闭。失败的访问不默认消耗行动；只有进入机构并确认办理后才扣除行动。

## 个人表单库存

玩家购买的是空白表单，而不是立即获得生活效果。

- 空白表单进入个人档案袋。
- 同一类型允许持有多份。
- 表单具有编号、版本、签发机构、工本费和有效期。
- 旧版本表单可能被拒收。
- 部分表单还需要附件。
- 每晚回家后最多填写并提交一张。

提交后进入 `pending` 状态。表单可能当晚生效、次日生效、延迟审查或被退回。

## 首发四种生存表单

### 居民饮水配额领取申请

- ID：`PERSONAL-FORM-WATER-R01`
- 地点：配给站
- 建议工本费：5
- 使用频率：每两天一次
- 生效：次日
- 缺失后果：脱水；次日拖拽物件出现轻微迟滞，工作时间缩短。

### 工作通勤许可

- ID：`PERSONAL-FORM-TRANSIT-T14`
- 地点：交通管理局
- 建议工本费：8
- 有效期：若干工作日
- 生效：次日
- 缺失后果：迟到、减少工作时间并扣除部分日薪。

### 住宅供电续接申请

- ID：`PERSONAL-FORM-POWER-E09`
- 地点：住房管理处
- 建议工本费：12
- 使用条件：收到停电通知
- 生效：当晚或次日，取决于表单版本
- 缺失后果：夜间无法填写复杂表单，部分事件通知不可读。

### 基层医疗接诊登记

- ID：`PERSONAL-FORM-MEDICAL-M04`
- 地点：基层医疗站
- 建议工本费：15
- 使用条件：生病或受伤
- 生效：延迟一日
- 缺失后果：状态逐日恶化，审批画面出现间歇模糊与轻微手抖。

## 事件通知与解法

日报结束后，系统生成一至两份个人通知。通知只描述事实、适用机构和表单编号，不直接给出操作指令。

示例：

> 第十二区住宅供电将于 24:00 中止。  
> 已登记住户可依 E-09 程序申请续接。

玩家需要：

1. 阅读通知。
2. 在地图上找到正确机构。
3. 购买正确版本的空白表单。
4. 回家填写。
5. 等待表单生效。

买错机构、买错版本、填写错误或缺少附件都会导致退件。工本费和已经消耗的行动不返还。

## 表单与次日操作后果

生活状态需要改变实际手感，而不只是修改数值：

- 缺水：拖动响应略慢，工作日时间缩短。
- 迟到：开场队列已经积压，减少可用时间和收入。
- 停电：夜间界面照明不足，无法处理复杂个人表单。
- 生病：视觉偶发模糊，鼠标操作产生轻微扰动。
- 充分休息：减少上述影响，但不替代有效表单。

负面效果必须保持可玩，不能造成玩家无法恢复的操作死锁。

## 配置本体

地图系统继续使用稳定 ID 和关系配置。

### 核心对象

- `location`：地点与机构
- `route`：地点之间的路线
- `personal_form_type`：个人表单定义
- `inventory_item`：持有的空白或已填写表单
- `personal_need`：饮水、通勤、供电、健康事实
- `evening_event`：夜间事件通知
- `personal_rule`：表单需求与生效条件
- `personal_consequence`：次日效果

### 关系示例

```text
LOCATION-RATION --sells--> PERSONAL-FORM-WATER-R01
NEED-DEHYDRATION --resolved_by--> PERSONAL-FORM-WATER-R01
PERSONAL-FORM-WATER-R01 --requires_visit--> LOCATION-RATION
PERSONAL-FORM-WATER-R01 --prevents--> CONSEQUENCE-DEHYDRATED
```

地点、路线、商品和事件均由配置驱动。地图脚本只负责呈现、选择和移动，不写死具体表单。

## 状态保存

`WorkdayState` 后续需要保存：

- 当日剩余夜间行动
- 当前所在地点
- 金钱与欠款
- 空白表单库存
- 已填写和待审表单
- 个人需求状态
- 已读通知
- 地点开放状态
- 延迟生效与退件队列

进入下一天前必须保存，避免地图或回家流程中断后丢失进度。

## 首版实施范围

首版实现：

1. 日报后进入地图。
2. 三个可见节点：中央表单部、配给站、住宅。
3. 两次行动与 Token 移动。
4. 配给站购买饮水表。
5. 回家填写并提交饮水表。
6. 次日生效或退件。
7. 缺水对次日工作时间产生实际影响。

交通、供电、医疗和职务插队保留完整配置结构，后续逐日开放。

## 验收标准

- 日报不会直接进入下一天，而是进入下班地图。
- 地图节点可点击，Token 移动和行动扣除一致。
- 玩家可以购买实体空白表单并在档案袋中看到它。
- 回家后可以填写并提交一张表单。
- 存档可以恢复地图、库存、需求和待审状态。
- 饮水表的成功与失败会影响次日工作。
- 地图和表单素材均为可独立使用的文件资产。
