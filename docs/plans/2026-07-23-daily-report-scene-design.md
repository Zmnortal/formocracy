# FORMOCRACY 工作日处理回执场景设计

## 目标

新增第二个 Godot 场景 `daily_report.tscn`，作为一天工作完成后的内部日报。页面只陈述审批官实际完成的操作，不提供分数、评级、金币、经验或决定正确性判断。

## 触发与流程

主工作台记录本工作日处理过的案件。当完成预设数量后，在最后一份材料结束验收过场后切换到日报场景。日报确认后开始下一工作日，清空当日记录并返回主工作台。

第一版以三份申请构成一个工作日，便于完整体验和测试。该数量属于原型节奏参数，不写入世界观文案。

## 日报内容

- 机构名称、工作日编号、生成时间和回执序号。
- 已完成形式审查、送交验收、批准、驳回和退回补正数量。
- 已批准事项与已取得现实效力事项分栏显示。
- 当日处理的住房、饮水和医疗申请摘要。
- 设施容量与等待状态的官僚式通告。
- 代理审批官记录确认声明。
- “确认并结束工作日”操作按钮。

## 视觉设计

页面表现为内部终端与打印回执的组合：深色 CRT 背景、绿色和琥珀色像素文字、窄像素边框、纸张回执、扫描线和轻微屏幕闪烁。所有界面使用像素字体；正文优先使用 Ark Pixel Font 简体中文版本，并通过 Godot 字体回退避免开发中字体尚未覆盖的汉字缺失。

Ark Pixel Font 随项目保留 SIL Open Font License 1.1 文本和来源说明。字体按原生像素尺寸或整数倍渲染，纹理过滤关闭，避免边缘模糊。

## 数据结构

新增跨场景工作日状态，保存工作日编号与当日案件记录。每条记录包含案件类型、申请人、印章类型、是否送交验收和验收状态。主场景只写入事实；日报场景负责聚合和显示。

## 错误处理

- 日报场景在没有案件记录时仍能显示零值回执。
- 字体加载失败时自动回退到 Godot 默认字体。
- 切换场景失败时保留当前工作日数据，不提前清空。
- 重复确认按钮在第一次点击后立即禁用。

## 验证标准

- 完成三份申请后自动进入 `daily_report.tscn`。
- 日报统计与实际批准、驳回操作一致。
- 日报显示完整中文像素字体且没有明显模糊。
- 确认日报后返回主场景并进入下一工作日。
- 工作日数据正确清空，工作日编号递增。
- Godot 解析、场景切换和自动化流程测试通过。
