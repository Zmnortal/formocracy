# FORMOCRACY 七日 Demo 特殊故事线总览

## 目的

本目录用于整理七日 Demo 中约 30% 的剧情表单。它们不是独立插入的“主线任务”，而是伪装成普通行政需求的连续案件。

七日共处理 35 宗案件：

- 24 宗 General 随机案件，约占 68.6%。
- 11 宗特殊剧情案件，约占 31.4%。

General 案件负责训练规则、维持行政工作的日常感和提供随机性；特殊剧情案件负责人物回访、线索积累、制度冲突与结局分支。

## 推荐的四条故事线

| 故事线 | 核心人物 | 表面问题 | 深层问题 |
|---|---|---|---|
| 01 共同居住与失踪的三个月 | 林默、沈青禾 | 两人能否正式共同居住 | 林默失踪期间到底在哪里，谁改动了他的住所记录 |
| 02 被改动的时间与生存资源 | 许桥、杜春梅、周循、宋铎 | 医疗通行、代领与资源排序 | 验收机时间是否被人为修改，合法程序为何持续伤害同一批人 |
| 03 提前发生的污染与被封存的人 | 孟秋兰、顾原、罗雨棠 | 污染救助与事故档案解封 | 官方事故日期是否虚假，被注销的工人是否仍存在于其他记录中 |
| 04 合法特权与最后一次盖章 | 玩家、魏岚、蒋森及前三线人物 | 一张完全合法的保障券 | 玩家最终维护的是程序正确、公共利益，还是自己的安全 |

## 七日线索递进

### Day 1：把人物放进规则

玩家第一次见到林默。他不是主角，而是一名谨慎、明显有所隐瞒的 NPC。案件看似只是共同居住，实际引出沈青禾的外区身份。

### Day 2：第一次怀疑系统

许桥的医院证明与验收记录相差二十三分钟。他坚持自己按时提交。此时没有证据证明机器有问题。

### Day 3：不同人物说出同一个缺口

杜春梅写下一个系统中不存在的人名；沈青禾的材料显示林默曾有三个月没有任何有效住所。两条线开始暗示：城市能够让人从记录中消失。

### Day 4：机器并不自动

宋铎承认验收机时间曾接受人工校准，但拒绝说明是谁下令。玩家获得第一条能够解释许桥材料异常的外部证词。

### Day 5：错误日期可能是真相

孟秋兰的污染检测早于官方事故日期。按照新手册，这像伪造；结合宋铎的证词，它也可能证明事故被推迟登记。

### Day 6：旧页与新页互相冲突

林默的住所记录连接到污染地点。孟秋兰要求解封儿子的档案，而旧版手册允许她申请，新修订页却删除了关键条款。

### Day 7：程序正确不再等于正确

工厂要求续封事故档案，主管家属要求兑付保障资源。两份材料都可以完全合法。玩家必须决定是否继续把“没有材料错误”当作唯一判断标准。

## 推荐的底层事实

七日 Demo 不需要把全部真相直接说完，但内部创作需要共享同一版本：

1. 第七码头附近的污染和夜间装配事故发生时间早于官方公告。
2. 一批夜班人员在事故后被从住所、配给和劳动记录中拆分或注销。
3. 孟秋兰的儿子属于这批人；顾原保留过名单，罗雨棠保留过最后乘车票根。
4. 林默失踪的三个月里曾被临时调往事故区域维护信号，因此住所记录出现空白。
5. 许桥运送过与事故有关的封存袋，并在途中受伤。
6. 验收机时间被人工调整，使一部分在截止线附近提交的材料自动失效。
7. 宋铎知道机器被调整，但不知道完整命令链；魏岚知道程序变更，却未必知道现场事实。

## 分支原则

- 每条线至少允许“批准、驳回、延迟”产生不同回访。
- 单次错误不应立即终止主线，人物可以通过补件、夜间接触或第三方证据再次出现。
- 玩家不能通过一张文件得到完整真相，至少需要两个不同来源互相印证。
- 结局不按“收集到几个线索”简单计分，而应同时读取玩家的程序记录、保留证据、人物信任和公共伤害。
- General 案件不改变主线变量，但可以重复使用相同规则，让玩家在剧情案件到来前学会对应操作。
